# أميال باي — مهمة تدقيق وإغلاق قطاع المناطق ونطاق التشغيل

هذه مهمة تطوير وإصلاح **كاملة في جولة واحدة متصلة** لشاشة:

`لوحة الإدارة → نطاق التشغيل والمناطق`

والشاشات/المسارات المرتبطة بها، بما في ذلك أي محرر قديم أو API إداري يغيّر `zone_code`.

لا تعد لي بعد كل Bug. نفّذ حتى نهاية القطاع:

`Audit → Truth Mapping → Policy Truth → Geography Truth → Enforcement Truth → RBAC → Fix → Unify → Redesign → Wire → Security → Concurrency → E2E → Production Verification → Regression → Final Verdict`

لا تعتبر الصفحة مكتملة لمجرد أنها تعرض المحافظات أو أن زر «إسناد المنطقة» يعمل.

المطلوب إنهاء **قطاع المناطق والسياسة الجغرافية بالكامل**:
Backend + Services + DB + Policy + KYC assignment + admin control + RBAC + Audit + AML integration + agent location enforcement + mobile UI + tests + production truth.

استخدم مهارات Amial المناسبة، خصوصًا:

`amial-admin-command`  
`amial-financial-truth`  
`amial-rbac`  
`amial-bug-hunter`  
`amial-regression-auditor`  
`amial-post-change-guardian`  
`amial-banking-ui`  
`amial-interactive-ui`

# 4. أهم Truth Check: هل AMIAL_OPERATIONAL_GOVERNORATES يغيّر التنفيذ فعلاً؟

الشاشة تقول إن نطاق التشغيل يُضبط بواسطة:

`AMIAL_OPERATIONAL_GOVERNORATES`

وأن تغيير القائمة يغيّر النطاق التشغيلي.

لكن `ZonePolicyService` ما زال يعتمد في القرار الأساسي على ثابت:

`ALLOWED_OPERATIONAL_ZONE = SOUTH`

أثبت فعليًا:

هل تغيير `operational_governorates` يغيّر **كل العمليات المالية التي يجب أن تتغير**؟

اختبار حاسم:

1. اختر محافظة جنوبية تتحول إلى `SOUTH`.
2. أخرجها من `operational_governorates`.
3. أنشئ حسابًا residence فيها.
4. اسند له `zone_code = SOUTH`.
5. جرّب كل عملية نقدية.

إذا بقيت العملية مسموحة لأن ZonePolicy يرى `SOUTH` فقط:

فهناك **Policy Truth Split**:

`Dashboard scope != Financial enforcement scope`

وهذا Bug حرج.

الهدف:

`operational scope displayed = operational scope enforced`

بدون استثناءات صامتة.

# 11. من هو الطرف الحاسم في Cash Boundary؟

التعليق يقول:

الطرف الحاسم في العمليات النقدية هو **الوكيل أو التاجر** وليس العميل.

لكن `EnforceZonePolicy` يستدعي:

`authorize($request->user(), action)`

أي غالبًا يحكم على المستخدم المصادق.

أثبت لكل Cash Boundary:

- من هو actor؟
- من يلمس النقد؟
- من هو counterparty؟
- أي zone يجب أن تحكم؟

مثال Merchant Payment:

عميل في NORTH يدفع لتاجر معتمد داخل نطاق التشغيل.

إذا كانت السياسة تقول إن عقدة التاجر هي الحاسمة:

لا يجوز منع العملية لمجرد `customer.zone_code = NORTH`.

وبالعكس لا يجوز السماح لعميل SOUTH بالدفع لتاجر خارج نطاق التشغيل.

ابنِ:

`ZoneDecisionContext`

يحتوي على:

`actor_zone`

`counterparty_zone`

`cash_node_zone`

`device_governorate`

`operation`

`policy_version`

ثم اجعل القرار مبنيًا على الطرف الصحيح.

# 28. Agent Location Mode Truth

الشاشة تعرض:

`soft / strict / off`

لكن لا يكفي Badge.

أثبت معنى كل وضع من الشيفرة الفعلية.

خصوصًا:

### soft
إذا الموقع مفقود، العملية تمر ويُكتب Laravel warning فقط.

إذن اللوحة تحتاج إظهار:

`cash operations without location`

وليس فقط blocked outside-zone.

### strict
غياب GPS يسبب رفضًا.

يجب أن يظهر كـViolation/Blocked metric.

### off
التعليق يقول «تسجيل فقط».

لكن افحص التنفيذ: إذا `mode === off` ويرجع مباشرة بدون تسجيل، فهذه وثيقة كاذبة.

إما:
- سجّل فعلاً في off،
- أو صحح التعريف.

أريد:

`agent location mode UI == runtime behavior`
