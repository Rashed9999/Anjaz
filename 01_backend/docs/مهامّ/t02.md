# أميال باي — مهمة إغلاق شاشة إدارة النطاقات القديمة وتوحيد توزيع المستخدمين مع مركز المناطق

هذه المهمة ليست إنشاء مركز مناطق جديد من الصفر.  
هذه الشاشة:

`لوحة الإدارة → توزيع المستخدمين على المناطق`

هي **محرر قديم وموازٍ** لقطاع المناطق الذي يجب أن يكون له مركز موحد واحد.

المطلوب:

`Audit → Prove Duplication → Prove Policy Drift → Lock Legacy Mutations → Route Unification → Domain-Service Migration → RBAC → Data Repair → UI Merge → Regression → Production Verification → Final Verdict`

لا تعالجها كتجميل مستقل.  
لا تترك صفحتين تدير `users.zone_code`.

الهدف النهائي:

`ONE ZONE ADMIN CENTER`
+
`ONE ZONE ASSIGNMENT SERVICE`
+
`ONE ZONE POLICY TRUTH`

---

## 1. أثبت أن هذه الشاشة Legacy

المسار الحالي:

`GET /admin/amial/zones`

و:

`POST /admin/amial/zones/update`

يتعاملان مباشرة مع `ZoneManagementController`.

في المقابل المشروع لديه:
- `ZoneControlController`
- `AdminZoneController`
- `ZoneAssignmentService`
- مركز «نطاق التشغيل والمناطق»
- مسارات إسناد من KYC

أنشئ Inventory كامل لكل واجهة/Controller/Command/API يقرأ أو يكتب `zone_code`.

النتيجة المطلوبة:

`zone mutation entry points = documented`

ثم بعد الإصلاح:

`authoritative zone mutation implementation = 1`

---

## 2. أخطر مشكلة: Controller القديم يكتب user.zone_code مباشرة

الحالي يفعل:

`$user->zone_code = $newZone;`
`$user->save();`

ولا يمر عبر `ZoneAssignmentService::assignByAdmin()`.

هذا bypass لـ:
- assignment history
- assignment method
- domain rules
- future approval
- concurrency
- role-specific restrictions
- KYC context

شرط الإغلاق:

`direct admin zone writes = 0`

---

## 3. هذه الصفحة تعطي وصفًا قديمًا للسياسة

UI تقول:

`SOUTH (can transact)`

و:

`Other zones (read-only)`

وداخل Modal:

`Only SOUTH allows financial operations. Other zones = read-only.`

لكن `ZonePolicyService` الحالي يسمح خارج SOUTH بعمليات Ledger داخلية مثل:
- send_money
- request_money
- refund
- split_bill
- donate
- safe payment ledger actions
- family fund actions

إذن الشاشة تعرض **Policy قديمة**.

شرط:

`stale SOUTH/read-only admin claims = 0`

---

## 4. لا تعدّل النص فقط

المشكلة ليست Translation.

يجب أن تُبنى Labels من Policy Registry الحقيقي.

مثلاً:

SOUTH:
`عمليات دفترية + عمليات حدود نقدية حسب السياسة`

NORTH/MIDDLE/OTHER:
`عمليات دفترية مسموحة، والعمليات ذات الحد النقدي تخضع لقيود`

UNKNOWN:
`لا عمليات مالية حتى اكتمال إسناد المنطقة`

لا hardcode الجملة في Blade.

---

## 5. buildSessionPolicy vs authorize

أعد اختبار التناقض المعروف:

`authorize()`
يسمح Ledger خارج SOUTH.

لكن `buildSessionPolicy()`
قد يجعل `can_transact=false` ويعيد financial actions فارغة.

هذه الشاشة القديمة تزيد المشكلة لأنها تشرح السياسة القديمة نفسها.

شرط:

`admin policy labels == backend authorize == session policy`

## 99. التقرير النهائي فقط

### BEFORE
كيف كانت شاشة إدارة النطاقات القديمة.

### DUPLICATION
كل المحررات والمسارات المتوازية.

### POLICY DRIFT
كل نص/رقم لا يطابق ZonePolicyService.

### LEGACY BYPASS
كيف كان Controller/CLI يتجاوز Domain Service.

### UNIFIED ARCHITECTURE
المركز الوحيد والخدمة الوحيدة.

### RBAC
من يرى ومن يغير ومن يعمل override.

### KYC & GEOGRAPHY
مصدر المنطقة وعلاقة السكن/الأصل.

### ROLE IMPACT
عميل/تاجر/وكيل.

### AUDIT & HISTORY
كيف يعاد بناء كل تغيير.

### CONCURRENCY
stale edits/idempotency.

### MIGRATION
كيف أغلقت legacy routes والبيانات القديمة.

### UI & MOBILE
كيف أصبحت القدرات داخل المركز الموحد.

### TESTS
كل الحراس والـregression.

### PRODUCTION TRUTH
الـcommit والمسار الفعلي المنشور.

### REMAINING
أي شيء لم يثبت.

ثم حكم واحد فقط:

`LEGACY ZONE MANAGEMENT SCREEN CLOSED & MERGED`

أو:

`SECTOR NOT CLOSED`

مع السبب.

بعدها توقف ولا تبدأ شاشة أخرى حتى أرسلها.
