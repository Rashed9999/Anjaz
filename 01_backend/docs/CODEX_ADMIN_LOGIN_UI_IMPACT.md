# تحليل أثر — واجهة دخول الإدارة

## الهدف

إصلاح صفحة `/admin/auth/login` الظاهرة فعلياً في الإنتاج: تحميل نظام الهوية
المفقود وإعادة بناء واجهة دخول الإدارة وصفحة التحقق الثنائي بصورة احترافية
ومتناسقة، من دون تغيير منطق الدخول أو الصلاحيات.

## الملفات المستهدفة

| الملف | التغيير المباشر |
| --- | --- |
| `admin-views/auth/login.blade.php` | هوية مرئية، CAPTCHA واضح قابل للتحديث، حالات خطأ، وتحسين استخدام الهاتف. |
| `admin-views/auth/two-factor.blade.php` | نفس الهوية ومسار الرجوع بعد كلمة المرور. |

## التبعيات والأثر

`GET /admin/auth/login` → `LoginController::login` → `auth.login` view.

`POST /admin/auth/login`، CAPTCHA، حماية حساب الإدارة، إعادة توليد الجلسة،
وتحويل 2FA تبقى بلا تعديل. صفحة 2FA تبقى على مساراتها الحالية.

| المجال | الأثر | الضبط |
| --- | --- | --- |
| المصادقة والصلاحيات | غير مباشر | لا تغيير للحقول أو أسماء الطلب أو الحارس أو المسارات. |
| CAPTCHA | مباشر في العرض فقط | يبقى مصدر الصورة الحالي، ويضاف زر تحديث يغيّر المصدر فقط. |
| 2FA | مباشر في العرض فقط | يبقى التحقق الخادمي ومسار الإلغاء كما هما. |
| التنقل | مباشر | رابط «العودة للموقع» فقط؛ لا رابط إلى لوحة أو مسار محمي. |
| التطبيق / المال / قاعدة البيانات | لا أثر | لا تغيير. |

## التوافق

- تبقى حقول `phone`, `password`, `default_captcha_value`, `remember` وCSRF.
- تبقى معرّفات الاختبار الحالية ولا تزال صالحة.
- لا تغيير لعقد POST أو CAPTCHA أو 2FA أو أي صلاحية.

## الظهور والوصول

يظهر في: الموقع ← «بوابة الإدارة» ← `/admin/auth/login`.

يُوصل إليه من: رابط بوابة الإدارة في الموقع؛ وبعد النجاح يتابع إلى لوحة
الإدارة أو إلى `/admin/auth/two-factor` عندما تكون 2FA مفعّلة.
