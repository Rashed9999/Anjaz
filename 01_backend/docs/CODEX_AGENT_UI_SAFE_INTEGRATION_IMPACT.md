# تحليل أثر — دمج واجهة تشغيل الوكيل الآمنة

## الهدف

نقل التحسينات المرئية والتشغيلية من الالتزام المحلي `aef1552` إلى قاعدة النشر
`f572574` من دون نقل التراجعات الأمنية أو إفساد دقة الأرقام المالية.

## الملفات المستهدفة

| الملف | الأثر المباشر |
| --- | --- |
| `AgentPortalController` | قراءة مؤشرات محصورة بالدور وإضافة قائمة المتابعة. يبقى محدد محاولات الدخول كما هو. |
| `AgentTellerController` و`AgentTellerRequestService` | عرض ومعالجة بلاغات الطوارئ للمدير فقط؛ لا حركة مال. |
| `routes/agent.php` | مسارا قراءة/قرار داخل وسيط `agent.portal` القائم. |
| `agent-views/dashboard` و`_workspace` | تنظيم لوحة المدير، نوافذ Bootstrap، وروابط متابعة قابلة للضغط. |
| اختبارات العقد ومساحة عمل الصراف | إثبات نطاق المدير، وحظر الصراف من إدارة الطوارئ. |

## الرسم التبعي

`agent.portal middleware` → `AgentPortalController::overview` → واجهة لوحة الوكيل

`agent.portal middleware` → `AgentTellerController` → `AgentTellerRequestService`
→ `AgentPanicAlert` → سجل التدقيق.

البيانات المالية المعروضة تبقى من الاستعلامات الخادمة الموجودة؛ JavaScript يعرض
السلاسل العددية فقط ولا يحسب رصيداً أو عمولة أو تسوية.

| المجال | الأثر | الخطر | الضبط |

| Flutter / قاعدة البيانات / التسوية | لا أثر | — | لا تغيير. |

## التوافق

- لا يُحذف مسار قائم ولا يتغير عقد `agent.overview` القديم؛ تضاف مفاتيح `attention` و`variance_total` فقط.
- تبقى مفاتيح `shortage_*` و`overage_*` لتوافق الواجهات والتقارير السابقة.
- الصراف لا يرى بطاقة الطوارئ ولا يستطيع إدارة بلاغ عبر نقطة النهاية.

## ترتيب التنفيذ والتحقق

1. تطبيق رقعة `aef1552` في مساحة نظيفة.
2. إعادة محدد محاولات الدخول وتنسيق الأرقام ومفاتيح الفروق الدقيقة.
3. مراجعة المسارات والنطاق وتدقيق قرارات الطوارئ.
4. تشغيل `bash scripts/verify.sh`، وفحوص العقد/الواجهة ذات الصلة عند توفر البيئة.

## الظهور والوصول

يظهر في: بوابة شركات الصرافة ← لوحة المدير ← تبويب «الرئيسية» و«المتابعة».

يوصل إليه من: بطاقة «راجع المتابعة» وبطاقات عناصر الانتباه؛ الصراف يظل في
تبويب «الشباك» ولا يرى وظائف إدارة الطوارئ.
