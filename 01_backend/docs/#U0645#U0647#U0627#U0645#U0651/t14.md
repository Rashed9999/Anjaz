# أميال باي — مهمة تدقيق وتطوير مركز الدعم والتشغيل

هذه مهمة **تدقيق وإصلاح وإعادة تصميم كاملة في جولة واحدة متصلة** للشاشة:

`لوحة الإدارة → العملاء → مركز الدعم (بحث شامل + الأجهزة)`

والتبويبات المرتبطة بها:

- خدمة العملاء
- فحص عملية
- التذاكر
- الموافقات
- الأمن الداخلي
- المراقبة

وكل API / Service / Model / Permission / Audit / Device / Ticket / Transaction / Approval / Insider / Health endpoint خلف هذه الشاشة.

لا تعد بعد كل Bug. نفّذ:

`Audit → Truth Mapping → Permission Mapping → Data Truth → Financial Trace → Security Actions → Ticket Workflow → Device Trust → Insider Controls → Monitoring Truth → Fix → Redesign → Wire → E2E → Regression → Production Verification → Final Verdict`

لا تعتبر القطاع مكتملًا لأن الصفحة تفتح أو لأن البحث يعيد JSON أو لأن زرًا يرسل Request.

المطلوب إنهاء **مركز الدعم والتشغيل بالكامل**:
Backend + Service Layer + RBAC + PII + Audit + Devices + Sessions + Customer 360 + Transaction Trace + Ledger + Tickets + Approvals + Insider Monitoring + Health + UI + Mobile + Tests + Production Truth.

# 2. أصلح صلاحية الصفحة نفسها

الصفحة الرئيسية:

`GET /admin/support-center`

تُفتح لأي مستخدم يمر من middleware `admin`.

بينما الـendpoints الداخلية لها Permissions مختلفة.

هذا يجعل موظفًا يرى:
- خدمة العملاء
- التذاكر
- الموافقات
- الأمن الداخلي
- المراقبة

حتى لو لم يملك صلاحية استخدامها.

لا تعتمد على أن الضغط سيعيد 403.

أنشئ Permission-aware shell:

- لا تعرض Tab لا يملك الموظف صلاحيتها.
- لا تحمل endpoint غير مسموحة.
- إذا لا يملك أي صلاحية داخل المركز → 403 للصفحة نفسها.
- Sidebar لا يعرض المركز لمن لا يملك أي Capability فعلية فيه.

أريد:

`visible unauthorized tabs = 0`

# 4. مركز الدعم ليس بحث عملاء فقط

البحث الحالي قد يعيد أنواع Users مختلفة:
- Admin
- Agent
- Customer
- Merchant

بينما الواجهة تسمي النتائج «العملاء».

قرر الحقيقة:

### إذا المركز مخصص للعملاء:
قيّد البحث بـ CUSTOMER_TYPE.

### إذا هو بحث موحد للأشخاص:
غيّر التسمية إلى:
**الحسابات**
وأظهر النوع بوضوح.

لا تسمح لموظف Support عادي بفتح ملف Admin عن طريق بحث الاسم/الهاتف ما لم تكن هناك صلاحية صريحة.

أريد:

`cross-role data leaks = 0`

`identifier type → normalization → table/model → permission → result type`

# 8. PII في نتائج البحث

- permission لكشف الرقم الكامل.
- reason when revealing high-risk PII إن كانت السياسة تتطلب.
- audit وصول مناسب.

لا تعرض بريدًا أو IP أو device fingerprint دون حاجة.
