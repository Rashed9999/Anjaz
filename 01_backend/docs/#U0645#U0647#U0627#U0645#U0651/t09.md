# أميال باي — مهمة تدقيق وإعادة بناء **رصيد المنصة + المركز المالي + الخزينة + الإصدار الإلكتروني**
## Bank-grade / E-Money-grade Financial Control Architecture

> **النطاق:** الشاشتان المرسلتان تُعاملان كقطاع مالي واحد مترابط:
>
> 1. `رصيد المنصة (E-Money)`
> 2. `المركز المالي`
>
> ولا يجوز إصلاح واحدة وترك الأخرى، لأن كلتيهما تعرضان/تحركان نفس الحقيقة المالية من مسارات مختلفة.

---

# 0) الحكم المبدئي قبل التنفيذ

البنية المالية في المشروع تحتوي عناصر قوية:
- Double-entry Ledger
- Journal Entries
- Idempotency
- Row Locks
- Reversals بدل حذف التاريخ
- Ledger Center
- Nightly Reconciliation
- Agent Cash/Till Reconciliation

لكن **الشاشتين الحاليتين ليستا بعد Bank-grade / E-Money-grade Control Center**.

أخطر سبب:
هناك **مساران مختلفان لشحن/إنشاء رصيد المنصة**، وكلاهما يعتمد على نموذج Legacy يقوم بإضافة `CASH_IN` إلى محفظة الإدارة نفسها، ولا يثبت في نفس العملية:
- أصلًا نقديًا/بنكيًا دخل فعليًا
- حساب safeguarding/reserve
- قيد إصدار E-Money كامل
- Maker–Checker
- مرجع استلام خارجي
- مطابقة أصل ↔ التزام

والنتيجة أن النظام يستطيع زيادة الرصيد الإلكتروني برمجيًا، لكن لا يستطيع من نفس السجل إثبات **ما الأصل الحقيقي الذي يقابله**.

المطلوب في هذه المهمة ليس تحسين الأرقام أو البطاقات، بل إصلاح النموذج المالي نفسه.

# 1) إثبات ما تعرضه الصور فعليًا

## الشاشة الأولى — رصيد المنصة (E-Money)

تظهر تقريبًا:

- إجمالي الرصيد المُصدَر:
  `4,023,012,531,898.62 ر.ي`

- الأموال المتداولة:
  `12,451,904.62 ر.ي`

- رصيد الخزينة غير المتداول:
  `4,023,000,079,994.00 ر.ي`

- أرباح الرسوم:
  `0.00 ر.ي`

## الشاشة الثانية — المركز المالي

تظهر:

- محفظة الإدارة:
  `4,023,000,079,994 ر.ي`

- أرصدة العملاء:
  `257,454.50 ر.ي`

- أرصدة الوكلاء:
  `11,468,081 ر.ي`

- أرصدة التجار:
  `726,369.12 ر.ي`

ومجموع:

`257,454.50 + 11,468,081 + 726,369.12`
=
`12,451,904.62`

وهو بالضبط رقم "الأموال المتداولة" في الشاشة الأولى.

ثم:

`4,023,000,079,994 + 12,451,904.62`
=
`4,023,012,531,898.62`

وهو بالضبط تقريبًا رقم "إجمالي الرصيد المصدر".

إذن الشاشة الأولى لا تحسب تاريخ الإصدار النقدي/الإلكتروني؛
بل تجمع **الأرصدة الحالية**.

هذه حقيقة مهمة جدًا.

# 2) المشكلة الدلالية الأولى: "إجمالي الرصيد المصدر" ليس إصدارًا فعليًا

الكود القديم يحسب:

`total = admin_current_balance + all_other_current_balances`

هذا ليس بالضرورة:

`Lifetime E-Money Issued`

ولا:

`Net E-Money Outstanding`

ولا:

`Safeguarded Customer Funds`

ولا:

`Treasury Assets`

إنه ببساطة مجموع أرصدة EMoney الحالية.

صحح التسمية والحساب.

أريد تعريفات مالية واضحة ومنفصلة:

### E-Money Outstanding
إجمالي التزامات المنصة الإلكترونية تجاه الأطراف الخارجية.

### Platform Own Funds
أموال المنصة نفسها.

### Safeguarded Funds / Backing Assets
النقد/الحسابات البنكية/الأصول المسموح بها التي تقابل الـE-Money.

### Agent Float
الرصيد الإلكتروني المتاح للوكلاء.

### Merchant Balances
التزام تجاه التجار.

### Customer Balances
التزام تجاه العملاء.

### Pending / Held / Frozen
ليست أموالًا جديدة؛ هي حالات لنفس الالتزام.

لا تجمع هذه المفاهيم في Card واحدة.

- Cash
- Bank balance
- Safeguarded bank balance
- Settlement receivable
- Agent cash receivable

- Retained earnings

`Admin EMoney Wallet = Treasury`
