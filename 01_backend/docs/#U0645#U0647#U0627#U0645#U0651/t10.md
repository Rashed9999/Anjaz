# أميال باي — مهمة تدقيق وتطوير وإغلاق مركز حالة التشغيل والطوابير والمستندات

هذه مهمة **تدقيق وإصلاح وإعادة تصميم وإغلاق تشغيلي كاملة في جولة واحدة متصلة** للشاشة:

`لوحة الإدارة → الإعدادات والتشغيل → حالة التشغيل (الطوابير والمستندات)`

وكل ما خلفها من:
- `OpsConsoleController`
- `OpsHealthService`
- Queue configuration
- Queue workers / Supervisor
- `jobs`
- `failed_jobs`
- `GeneratePdfReceiptJob`
- `PdfCacheService`
- `ReceiptDocumentService`
- `ReceiptService`
- storage disks
- encrypted/private documents
- scheduler
- notifications
- PDF generation
- receipt regeneration/diagnosis
- RBAC
- Audit
- Coolify/production deployment truth
- filesystem persistence
- health signals
- mobile UI
- operational runbooks
- tests

لا تعد بعد كل Bug. نفّذ:

`Audit → Runtime Truth → Queue Truth → Worker Truth → Storage Truth → Document Truth → Failed-Job Truth → Diagnostic Safety → RBAC → Audit → Fix → Redesign → Wire → Failure Injection → E2E → Regression → Production Verification → Final Verdict`

لا تعتبر القطاع مكتملًا لأن الشاشة تقول `كل شيء يعمل` أو لأن جميع الأرقام صفر.

المطلوب أن تصبح هذه الشاشة **مركز الحقيقة التشغيلية للمنصة**، لا مجرد قارئ لثلاثة جداول ومجلدات.

---

## 1. Runtime Truth Map

ارسم:

`Application → Dispatch job → Queue connection → Queue name → Queue backend → Worker process → Worker subscribed queues → Reserved/running → Completed/failed → Side effect → Receipt/Notification/artifact → Storage → Customer-visible result → Ops Health`

ثم:

`Coolify container → entrypoint → supervisord → php-fpm → nginx → queue workers → scheduler → storage volume → DB/Redis/external dependencies`

ولا تعتمد على ملفات المستودع وحدها.

---

## 2. «كل شيء يعمل» أوسع من الحقيقة الحالية

الحكم الحالي يعتمد أساسًا على:
- stalled queue
- unwritable storage directory
- failed_jobs > 0

وهذا لا يثبت:
- worker processes alive
- scheduler alive
- queue backend reachable
- cache reachable
- PDF renderer healthy
- private document decrypt works
- storage persistent
- notification delivery healthy
- release parity

إما غيّر العنوان إلى **صحة الطوابير وتوليد المستندات**، أو وسّع القياس فعليًا إلى مركز تشغيل شامل.

شرط:
`overbroad green health claims = 0`

---

## 3. Queue backend ليس دائمًا جدول jobs

`OpsHealthService` يقرأ `jobs` مباشرة، بينما `config/queue.php` يدعم `sync/database/redis/sqs/beanstalkd`، والـdefault من `QUEUE_CONNECTION`.

أثبت قيمة production الفعلية.

ابنِ `QueueHealthAdapter` حسب driver:
- database → DB table
- redis → Redis health/queue metrics
- sync → no backlog semantics
- unsupported → UNKNOWN

شرط:
`queue health source == active queue backend`

---

## 4. UNKNOWN لا يتحول إلى صفر

إذا Source غير متاح أو adapter غير مدعوم:
لا تعرض `0`.

أعد:
- `status=unknown`
- `value=null`
- `error_code`

شرط:
`false-zero queue metrics = 0`

---

## 5. Worker Heartbeat

Queue فارغة لا تثبت أن worker يعمل.

أضف heartbeat لكل worker:
- worker id
- container/host
- process identity
- subscribed queues
- started_at
- last_heartbeat_at
- current job
- jobs processed
- failures
- memory
- last restart

اختبار:
`empty queue + dead worker = RED/UNKNOWN` وليس Healthy.

---

## 6. Supervisor Truth

أثبت runtime:
- supervisord alive
- expected process count == actual
- php-fpm running
- nginx running
- queue workers running
- scheduler running

ملف config ليس دليلًا أن العملية حية.

---

## 7. Worker Subscription Parity

Production supervisor يعلن queues:
`receipts,default,notifications`

ابحث repository-wide عن:
- `onQueue(...)`
- `$queue`
- dispatch to specific queue/connection
- listeners/jobs

قارن:
`all dispatched queue names`
مع
`all consumed queue names`

شرط:
`queues dispatched but not consumed = 0`

وأضف CI Guard لمنع تكرار عطل receipts القديم.

---

## 8. Queue Priority Starvation

الـworker يعمل:
`--queue=receipts,default,notifications`

اختبر starvation إذا receipts ممتلئ باستمرار.

اعرض:
- priority
- backlog
- oldest
- throughput
- p50/p95 queue wait

إن لزم افصل worker pools.

لا تجعل PDF يمنع Notifications المهمة.

---

## 9. Per-Queue SLA

لا تستخدم `STALL_SECONDS=300` لكل queue.

أنشئ:
`queue → warning_after → critical_after → expected_runtime → priority`

الـnotification ليست receipt، وbulk job ليست default interactive job.

## 11. Stale Reservation

## 12. Critical timeout/retry_after parity

Supervisor يستخدم `--timeout=600`.

Queue config الحالي يعرّف `retry_after=90` لـdatabase وredis.

أثبت Runtime values.

في Laravel يجب أن يكون `timeout < retry_after` مع هامش.

إذا production فعلًا 600 مقابل 90 فهناك خطر أن تُعاد المهمة بينما النسخة الأولى ما زالت تعمل.

شرط:
`worker timeout >= retry_after = 0`

---

## 13. Duplicate receipt rendering race

`GeneratePdfReceiptJob` يتحقق idempotently بعد اكتمال PDF، لكن Worker A وB قد يبدآن قبل أن يحفظ أحدهما.

اختبر نفس receipt concurrently.

استخدم distributed lock / unique job / atomic state.

شرط:
`concurrent duplicate receipt rendering = 0`

---

## 14. Retry policy source

Job لديه `$tries=3` وbackoff `[10,60,300]`.

Supervisor لديه `--tries=2`.

أثبت أيهما Effective في Laravel version المستخدمة، ووحّد Policy أو وثّق precedence.

شرط:
`retry policy ambiguity = 0`

## 15. Failed summary آخر 50 فقط

الحالي:
- `total` = كل failed_jobs
- `groups` = آخر 50

إما Group كامل بكفاءة، أو label واضح: **آخر 50 فشلًا**.

---

## 16. أخطر Group Retry mismatch

العرض يجمع حسب:
`job name + exception first line`

لكن Retry group يستخدم:
`queue + exception prefix`

ولا يثبت Job class.

قد يعيد Jobs مختلفة تشترك في نفس exception head.

أنشئ fingerprint ثابت:
`job_class + queue + normalized_root_cause`

واجعل:
`preview fingerprint == retry fingerprint`

`retry preview/actual mismatches = 0`

## 112. التقرير النهائي فقط

في نهاية الجولة أعطني:

### BEFORE
ما الذي كانت تقيسه الشاشة فعليًا.

### FALSE HEALTH RISKS
كل حالة يمكن أن تقول فيها Green بينما النظام مريض.

### RUNTIME TRUTH
الـcontainer/processes/workers/scheduler الفعلية.

### QUEUE TRUTH
connection/backend/queues/subscriptions/SLA.

### WORKER TRUTH
عدد العمال والheartbeat والtimeouts.

### FAILED JOBS
grouping/retry/quarantine/outcomes.

### DOCUMENT PIPELINE
Receipt → Queue → Renderer → Storage → Download.

### STORAGE
disks/persistence/replicas/capacity.

### DIAGNOSTICS
Read-only مقابل Mutation.

### RBAC
من يرى ومن يشخّص ومن يعيد.

### AUDIT
كل تدخل ومن نفذه ولماذا.

### INCIDENTS
فتح العطل وإغلاقه وتاريخه.

### UI
المركز الجديد والـdrill-down.

### MOBILE
الأحجام المختبرة.

### FAILURE INJECTION
الأعطال التي تم اختبارها.

### TESTS
كل الحراس والـregression.

### PRODUCTION TRUTH
commit + queue driver + Supervisor + storage الفعلي.

### REMAINING
أي شيء لم يثبت.

ثم حكم واحد فقط:

`OPS, QUEUES & DOCUMENTS ADMIN SECTOR CLOSED`

أو:

`SECTOR NOT CLOSED`

مع السبب.

بعدها توقف ولا تبدأ شاشة أخرى حتى أرسلها.
