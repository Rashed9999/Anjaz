# مهمة موحّدة — إصلاح الأمن والرقابة والحوكمة في أميال باي بجولة واحدة

## الهدف
تنفيذ جولة واحدة شاملة ونهائية لإصلاح وربط واختبار الشاشات التالية دون تقسيم العمل:
1) مراجعة مستندات الهوية KYC
2) صحة النظام System Health
3) حارس الأمان Security Sentinel
4) أحداث أمان الحساب
5) لوحة الإشراف
6) سجل تدقيق النظام

المطلوب ليس تجميل الواجهات فقط، بل ربط كل شاشة بمصدرها الحقيقي، منع الأرقام الوهمية، منع تحويل الأعطال إلى صفر، وتوثيق كل إجراء حساس في سجل التدقيق.

### المطلوب

- كل فتح لوثيقة هوية يسجل PII access.
- منع self-approval وIDOR.
- عدم كشف `encrypted_path` للمتصفح.
- عدم ترك ملفات مفكوكة في temp.

## 2. صحة النظام System Health
### الملفات الأساسية
- `01_backend/app/Http/Controllers/Admin/SystemHealthController.php`
- `01_backend/app/Services/SystemHealthService.php`
- `01_backend/app/Services/OpsAlertService.php`
- `01_backend/resources/views/admin-views/amial/system/health.blade.php`

### المشكلة
لا يجوز أن تظهر المنصة "سليمة" بينما توجد:
- `recon.nightly_diverged`
- قناة إنذار خارجية مفقودة
- Critical unresolved defects
- Scheduler/backup/ledger integrity غير مؤكدة

### المطلوب
إعادة تعريف Overall Health ليشمل:
Database, Cache, Queue, Storage, Disk, Runtime, Scheduler heartbeat, Queue worker heartbeat, Backup freshness, Nightly reconciliation, Ledger integrity, Audit integrity, External alert channel, Critical open defects.

الحالات الموحدة:
- healthy
- degraded
- critical
- unknown

قواعد:
- `recon.nightly_diverged` => ليس Healthy.
- غياب قناة إنذار خارجية => على الأقل Degraded.
- فشل Ledger/Reconciliation => Critical.
- مصدر غير معروف => Unknown/Degraded، وليس Healthy.

لكل عطل اعرض: الرمز، أول/آخر ظهور، التكرار، component، request/correlation id، الاستثناء المختصر، الحالة، ملاحظات الحل، وأزرار إقرار/حل/إعادة فتح.

أضف اختبار إرسال حقيقي لقناة التنبيه الخارجية مع تسجيله في Audit.

## 3. حارس الأمان Security Sentinel
### الملفات الأساسية
- `01_backend/app/Services/Security/SecuritySentinelService.php`
- `01_backend/app/Http/Middleware/SecuritySentinel.php`
- `01_backend/app/Http/Controllers/Admin/SentinelDashboardController.php`
- `01_backend/app/Services/Security/ThreatSignatures.php`
- `01_backend/config/security_sentinel.php`

### المشكلة
يوجد `monitor / challenge / block`، لكن Challenge يجب أن يصبح إجراءً حقيقياً لا مجرد اسم.

### المطلوب
- تنفيذ Step-Up Challenge حقيقي:
  - Login: rate limit + challenge/OTP/second factor حسب الخطر.
  - جلسة موثقة: re-auth/PIN/device confirmation.
  - API حساس: `challenge_required` بشكل آمن.
- تسجيل challenge started/passed/failed/expired.
- تحسين دورة حياة الحظر: blocked_at, blocked_until, reason, source, created_by, hits, last_hit_at, unblock reason/by/at.
- التحقق من Trusted Proxies وX-Forwarded-For في بيئة Coolify.
- إضافة اختبار يمنع حظر reverse proxy بدلاً من IP العميل.
- مراجعة auto-block ضد NAT/shared IP/admin lockout/internal services.
- تطوير Dashboard لعرض: severity/action/signature/path/user-agent distributions، authenticated vs anonymous، challenge success/failure، auto/manual blocks، unblock history.

## 6. سجل تدقيق النظام Audit Decisions
### الملفات الأساسية
- `01_backend/app/Http/Controllers/Admin/AuditDecisionsController.php`
- `01_backend/app/Services/AuditService.php`
- `01_backend/app/Models/AuditDecision.php`

### المشكلة
يجب ألا يوجد تعريفان مختلفان لسلامة السلسلة بين Audit وSupervision.

### المطلوب
إنشاء/اعتماد خدمة موحدة مثل `AuditIntegrityService` تكون المصدر الوحيد لـ:
- verify record hash
- verify prev link
- verify range
- verify latest N
- full scheduled verification
- integrity summary

وتستخدمها:
Audit screen, Supervision, System Health, scheduled verifier.

الحالات:
intact / broken / empty / unknown
و`empty != intact`.

كل صف Audit يفتح Drawer/Modal يعرض:
decision_id, actor, role, subject, action, decision code, severity, reason, transaction id, idempotency key, zone, request id، context، before/after إن وجدت، entry_hash، prev_hash، hash match، link match، رابط الموضوع.

CSV:
- يحترم الفلاتر
- يمنع CSV formula injection
- BOM للعربية
- صلاحية تصدير مستقلة
- يسجل عملية التصدير
- لا يصدر PII أعلى من صلاحية المستخدم

أضف فحصاً مجدولاً للسلسلة كاملة مع حفظ آخر نتيجة وإرسال Alert خارجي عند Broken.

## 7. الربط الإجباري بين الشاشات
- KYC decision → Audit → Supervision → PII log.
- Sentinel event → Account Security عند وجود user → Challenge/Block → Audit عند الإجراء الإداري.
- Audit integrity failure → System Health Critical → External Alert → Supervision warning.
- Reconciliation divergence → System Health Critical → External Alert → رابط مباشر لمركز الدفتر/المصالحة.
- فشل PII/KYC/Sentinel source لا يظهر كصفر.

## 10. الأعطال الظاهرة حالياً
عالج جذرياً، لا تخفِ:
- `ops.alert_channel_missing`
- `recon.nightly_diverged`
- `backup`
- `RelationNotFoundException`
- `ViewException`
- وأي defect مفتوح فعلي.

لكل عطل:
1. Root cause.
2. Fix.
3. Regression test.
4. Verify disappearance.
5. Resolve only after proof.

## 11. الاختبارات الإلزامية
### KYC
queue, self-approval, reject reason, encrypted access, IDOR, PII logging, OCR low confidence, expired document, verified national_id, unavailable != zero.

### Health
missing alert channel != healthy, reconciliation divergence=critical, stale scheduler, unresolved critical defect, unknown dependency, all-green path.

### Sentinel
scanner UA, empty UA, monitor, block, real challenge, trusted proxy, manual block/unblock, auto block, Account Security bridge.

### Account Security
PIN failures, filters, sentinel bridge, device/phone/recovery events, suspicious summaries.

### Supervision
PII unavailable != empty, KYC/AML/settlement pending buckets, SLA, outlier, self-action violation.

### Audit
entry mutation detected, prev-link mutation detected, same integrity state across Audit/Supervision/Health, empty != healthy, CSV filters, formula injection, export permission, scheduled full verify.

شغّل أيضاً الاختبارات المرتبطة بالدفتر والتسويات وAdmin reachability لمنع regression.

## 12. بوابات الإغلاق
لا تعلن:
`SECURITY_GOVERNANCE_SECTOR_CLOSED`

إلا إذا تحقق:
- KYC عملي بالكامل.
- OCR لا يقرر وحده.
- PII logging يعمل.
- Health لا يكذب بحالة Healthy.
- reconciliation/backup/scheduler/audit integrity داخلة في Health.
- Sentinel Challenge حقيقي.
- Trusted Proxy مثبت.
- Account Security مرتبطة بالأحداث الفعلية.
- Supervision لا تحول unavailable إلى zero.
- Audit integrity موحد.
- كل زر ظاهر له Backend action حقيقي.
- كل action حساس يسجل Audit.
- اختبارات الحزمة كلها خضراء.
- لا regression في المال/التسويات/API.
- تم إصلاح الأعطال الحالية من جذورها.

## 13. تقرير التسليم النهائي
قدّم تقريراً واحداً بعد الجولة فقط:
1. Files changed
2. Root causes fixed
3. Database/index changes
4. Security/RBAC changes
5. Monitoring changes
6. Tests + pass/fail
7. Remaining blockers
8. Final verdict:
   - `SECURITY_GOVERNANCE_SECTOR_CLOSED`
   - أو `SECURITY_GOVERNANCE_SECTOR_NOT_CLOSED`

المطلوب النهائي:
**هوية → أمان حساب → حارس → تدقيق → إشراف → صحة نظام → تنبيه خارجي**
منظومة واحدة مترابطة، لا ست صفحات منفصلة.
