# أميال باي — مهمة فصل بوابة الإدارة عن بوابة الموظفين وبناء دخول الموظفين حسب الصلاحيات

## القرار المعماري
الشاشة الحالية تبقى **بوابة الإدارة**:
`/admin/auth/login`

ويُنشأ مسار مستقل للموظفين:
`/staff/login`

لا تنشئ قاعدة مستخدمين ثانية ولا كلمات مرور منفصلة. استخدم نفس:
- users
- Roles
- Permissions
- 2FA
- Sessions
- Audit

لكن افصل **سطح الدخول، تصنيف الحساب، الصفحة الرئيسية، القائمة، والصلاحيات**.

---

## 1. حقيقة المشروع الحالية
الكود الحالي في:
`app/Http/Controllers/Admin/Auth/LoginController.php`

يسمح لأي حساب:
`type = ADMIN_TYPE`

ثم يعيد الجميع إلى:
`admin.dashboard`

وهذا يعني أن مدير المنصة والموظف التشغيلي يمران من نفس الباب إذا كانا من نفس النوع.

صفحة:
`resources/views/admin-views/auth/login.blade.php`

تعرف نفسها كـ:
`Admin Panel`

لذلك يجب إبقاؤها مخصصة للإدارة العليا فقط.

---

## 2. الأدوار الموجودة أصلًا
المشروع لديه RBAC جاهز يشمل:
- `platform_admin` — مدير المنصة
- `platform_support` — فريق دعم العملاء
- `platform_finance` — فريق المالية
- `platform_risk` — فريق المخاطر
- `platform_compliance` — فريق الامتثال

لا تعِد بناء RBAC من الصفر؛ ابنِ بوابة الموظفين فوق هذه الحقيقة.

---

## 3. بوابة الإدارة
`/admin/auth/login`

مخصصة فقط لـ:
- platform_admin
- أي دور إداري أعلى معتمد رسميًا

إذا حاول موظف دعم/مالية/مخاطر/امتثال الدخول منها:
- لا تنشئ Admin session
- أظهر رسالة آمنة بعد التحقق:
  `هذا الحساب مخصص لبوابة الموظفين`
- وفر انتقالًا إلى `/staff/login`

---

## 4. بوابة الموظفين
أنشئ:
`/staff/login`

العنوان:
**بوابة موظفي أميال باي**

وصف:
`دخول الموظفين المصرح لهم إلى أنظمة التشغيل والدعم والمالية والمخاطر والامتثال`

الحقول:
- رقم الهاتف أو معرف الموظف
- كلمة المرور
- التحقق الأمني
- 2FA
- زر دخول

لا تضع Dropdown لاختيار الدور؛ الموظف لا يختار صلاحياته بنفسه.

---

## 5. OperatorAccessResolver
أنشئ خدمة مركزية تعيد:
- platform roles
- effective permissions
- portal class
- default landing
- account status
- employee status
- 2FA requirement

مثال:
- platform_support → staff/support
- platform_finance → staff/finance
- platform_risk → staff/risk
- platform_compliance → staff/compliance
- platform_admin → admin dashboard

## 7. Backend Authorization
إخفاء عناصر القائمة ليس حماية.

كل Route يحتاج permission حقيقية.

شرط:
`staff direct URL access to unauthorized admin pages = 403`

وأضف:
`portal_context = admin | staff`

لكن يبقى RBAC هو المصدر النهائي للصلاحية.

---

## 8. 2FA
الكود الحالي يفرض 2FA فقط إذا كان الموظف قد فعله أصلًا.

في Production:
- platform_admin → 2FA إلزامي
- platform_finance → إلزامي
- platform_risk → إلزامي
- platform_compliance → إلزامي
- platform_support → الأفضل إلزامي

إذا لم يكن 2FA مضبوطًا:
- تحقق من كلمة المرور
- لا تنشئ جلسة كاملة
- حوّل المستخدم إلى Enrollment Gate
- بعد التفعيل أكمل الدخول

---

## 9. حالات الموظف
لا يكفي وجود Role.

اعتمد حالة:
- active
- suspended
- on_leave
- terminated
- locked_security

الموظف المنتهي:
- login denied
- revoke sessions
- revoke tokens
- revoke remember sessions
- disable role assignments
- audit

---

## 10. فصل الإدارة عن الموظفين
لا تجعل حساب الموظف يمر من بوابة Admin ثم تعتمد على Sidebar.

المطلوب:
`login surface → account classification → portal policy → RBAC → workspace`

وليس:
`ADMIN_TYPE → admin.dashboard`

## 11. تحسين شاشة الإدارة الحالية
الصورة الحالية تحتاج إعادة تصميم:
- بطاقة أكبر ومتوازنة
- هوية بصرية احترافية
- عبارة واضحة: `هذه البوابة مخصصة لإدارة المنصة`
- Captcha أوضح
- إظهار/إخفاء كلمة المرور
- Caps Lock indicator
- رسائل خطأ آمنة
- رابط مساعدة إدارية
- Production/Staging badge
- Mobile responsive

لا تعرض تفاصيل الدور قبل التحقق.

---

## 12. تصميم شاشة الموظفين
- شعار Amial Pay
- "بوابة الموظفين"
- خلفية مؤسسية هادئة
- بطاقة متوسطة بعرض مناسب
- touch targets مناسبة
- captcha readable
- RTL صحيح
- لا مساحة بيضاء ميتة ضخمة
- لا نفس نسخة Admin مع تغيير عنوان فقط

---

## 13. Session Security
بعد:
- password
- role resolution
- 2FA

نفّذ:
- session regeneration
- CSRF
- Secure/SameSite cookies
- idle timeout حسب الدور
- re-auth للأفعال الحساسة
- no long-lived remember for privileged roles إلا بسياسة واضحة

---

## 14. Login Audit
سجل:
- success
- failure
- wrong portal
- 2FA challenge/failure/success
- logout
- new device
- disabled employee attempt
- suspicious IP

ولا تسجل:
- password
- OTP
- captcha
- secrets

---

## 15. حماية من Enumeration
قبل إثبات كلمة المرور:
استخدم رسالة عامة:
`بيانات الدخول غير صحيحة أو الحساب غير مخول لهذه البوابة`

بعد إثبات الهوية فقط يمكن توجيهه إلى البوابة الصحيحة.

---

## 16. Staff Account Management
أضف/اربط شاشة:
`إدارة الموظفين والصلاحيات`

تحتوي:
- الاسم
- employee ID
- الهاتف
- الدور
- الحالة
- 2FA
- آخر دخول
- الجلسات
- تاريخ إنشاء الوصول
- انتهاء الوصول

الإجراءات:
- إنشاء
- تعليق
- إعادة تفعيل
- تعيين دور
- سحب دور
- reset 2FA
- revoke sessions
- إنهاء وصول

كلها:
Permission + Reason + Audit.

---

## 17. Role Conflict Policy
لا تسمح بجمع أدوار متعارضة بلا سياسة.

أمثلة:
- maker + checker
- money mover + reconciler
- KYC submitter + approver

أنشئ Guard يمنع تضارب الأدوار.

## 25. التقرير النهائي
أرسل تقريرًا واحدًا فقط:

### BEFORE
كيف كان الجميع يمر من باب Admin واحد.

### ADMIN PORTAL
من يحق له الدخول.

### STAFF PORTAL
الشاشة الجديدة والمسار.

### ROLE RESOLUTION
كيف يحدد النظام وظيفة الموظف.

### STAFF WORKSPACES
الدعم / المالية / المخاطر / الامتثال.

### RBAC
المسارات والصلاحيات.

### 2FA
كيف أصبح إلزاميًا.

### SESSIONS
الجلسات والإلغاء.

### SECURITY
Captcha / Rate limit / Enumeration / Device risk.

### UI
تطوير شاشة الإدارة وإنشاء شاشة الموظفين.

### MOBILE
نتائج 360/390/430/768/1024.

### TESTS
كل الاختبارات.

### PRODUCTION TRUTH
الـSHA الفعلي.

ثم حكم واحد فقط:

`ADMIN AND STAFF ACCESS PORTALS CLOSED`

أو:

`SECTOR NOT CLOSED`

مع السبب.
