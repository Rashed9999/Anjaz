# نظامُ تصميم أميال باي — والجسرُ إلى كلود ديزاين

> **مولَّدٌ آليّاً. لا يُحرَّر ملفُّ معاينةٍ بيد.**
> ```bash
> php design-system/build.php
> ```

---

## لمَ وُجد هذا المجلّد

كلود ديزاين يعمل على **معايناتِ HTML** — ملفّاتٌ يحمل كلٌّ منها في سطره
الأوّل `<!-- @dsCard … -->` فتُبنى منها بطاقاتُ اللوحة.

وواجهاتُ أميال باي ليست HTML:

| السطح | العدد | لغتُه |
|---|---|---|
| شاشات Flutter | ١٣٣ | Dart |
| ودجت مشتركة | ١٥٢ | Dart |
| قوالب Blade | ١٠٤ | PHP/HTML |

فلو رُبط كلود ديزاين اليوم بلا هذا المجلّد لوجد **مشروعاً فارغاً**. وهذا
الجسر: التوكِنزُ تُقرأ من الشيفرة وتُعرض بلغةٍ يفهمها.

---

## المصدرُ واحد، والمعايناتُ مشتقّة

```
02_flutter_app/lib/theme/amial_colors.dart      ← المصدر الأوّل
        │  (حارس: BrandIdentityGuardTest)
        ▼
01_backend/public/assets/css/amial-tokens.css   ← مرآةُ الويب
        │  (مولّد: design-system/build.php)
        ▼
design-system/foundations/*.html                ← معايناتُ كلود ديزاين
```

**ولا تُكتب قيمةٌ في معاينةٍ بيد.** فالقيمةُ التي تُنسخ تعيش وحدها وتفترق
عن مصدرها — وهو ما أنتج في هذا المشروع أزرقين لعلامةٍ واحدة: `#053391`
في التطبيق و`#0f2b46` في لوحة الإدارة.

وحارسُ `DesignSystemSyncTest` يُعيد التوليد ويقارن، فمن غيّر توكِناً ونسي
التوليد **يسقط عنده الفحص**.

---

## الربطُ بكلود ديزاين

**لا يُبدأ الربطُ من جهة الوكيل.** قِيس وثبت:

```
DesignSync ← الأداة موجودة
list_projects ← "needs design-system authorization, but /design-login
                 requires an interactive terminal and is not available
                 in this environment"
```

فـ`/design-login` يحتاج طرفيّةً تفاعليّة، وClaude Code على الويب ليس كذلك.

### الخطوات — من جهتك

1. افتح `claude.ai/design`
2. أنشئ مشروعاً واحرص أن يكون نوعُه **Design System**
   — النوعُ يُثبَّت عند الإنشاء ولا يتغيّر بعده، ودفعُ معايناتٍ إلى مشروعٍ
   عاديّ لا يجعله نظامَ تصميم
3. اضغط **«Send to Claude Code Web»** — تُبذَر الجلسةُ بالمشروع
4. في تلك الجلسة: `php design-system/build.php` ثمّ ارفع `foundations/`

### الاتّجاه الآخر

ما يُحسَّن في كلود ديزاين يعود إلى الشيفرة **عبر التوكِنز لا عبر الـHTML**:
تُعدَّل القيمةُ في `amial_colors.dart`، ثمّ `amial-tokens.css`، ثمّ يُعاد
التوليد. وحرّاسُ الهويّة تمسك أيَّ خطوةٍ تُنسى.

## عطلان كشفهما بناءُ الأساسات — قِيسا ولم يُصلَحا بعد

### ١. لا خطَّ عربيَّ في التطبيق إطلاقاً

```
Rubik-Regular.ttf : ٦٩٠ محرفاً
  النطاق العربيّ  (U+0600–U+06FF) : صفر
  الأشكال التقديميّة (U+FE70–U+FEFF) : صفر
  «أ» «م» «ي» : غيرُ موجودة
```

والتطبيق يفرض `languageCode = 'ar'` عند أوّل إقلاع، ويعلن
`fontFamily: 'Rubik'` في الثيم الفاتح و`'Roboto'` في الداكن — وكلاهما
بلا عربيّة، والداكنُ غيرُ محزومٍ أصلاً.

**فكلُّ حرفٍ عربيٍّ يراه العميل يرسمه خطُّ نظامِ جهازه** — يختلف بين سامسونج
وشاومي وآيفون، وبين إصدارين من النظام نفسِه. ولا خطأ في أيّ بناء ولا
تحذير في أيّ سجلّ: النصُّ يظهر، فيُظنّ محكوماً.

**الإصلاح:** حزمُ خطٍّ عربيٍّ (Cairo أو IBM Plex Sans Arabic أو Noto Kufi
Arabic) وتوحيدُ الثيمين عليه. **قرارُ علامةٍ لا إصلاحٌ صامت.**

### ٢. اللونُ الباهت لا يُقرأ

```
--amial-text-muted  #8B97A8
  على السطح الأبيض : 2.96:1   (WCAG AA = 4.5 · النصّ الكبير = 3.0)
  على الخلفيّة      : 2.67:1
  الاستعمال        : ١٨٥ موضعاً في ٧٤ ملفّاً
```

دون حدّ AA، **بل ودون حدّ النصّ الكبير**. وهذا تطبيقٌ يعرض مبالغَ مالية
ويُستعمل في شمس صنعاء على شاشاتٍ رخيصة.

**أقربُ إصلاحٍ يحفظ الصبغةَ والإشباع:**

```
#637084  →  على الأبيض 5.02:1  ·  على الخلفيّة 4.53:1   ✅ AA على السطحين
```

وهو مثبَّتٌ اليوم في `DesignSystemSyncTest::TEXT_TOKENS` بقيمته الحاليّة
**فلا يزداد سوءاً**، ويبقى ظاهراً في جدول الألوان حتّى يُحسم.
