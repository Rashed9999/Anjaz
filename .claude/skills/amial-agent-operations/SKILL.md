# عمليات وكيل أميال

## الهدف

حوّل متطلب الوكيل إلى عملية تشغيلية قابلة للتدقيق من دون نسخ المحفظة أو دفتر القيود خارج أميال باي.

## الحقيقة التشغيلية

- أميال باي هو المصدر الوحيد للرصيد والقيد والحدود المالية.
- الوكيل يملك حيازةً تشغيلية فقط: نقدية صندوقه، سيولته المصرح بها، ورديته، وطلبات التسوية الخاصة به.
- موثّق يقرر الهوية وحالة KYC؛ لا يحرّك نقدية الوكيل ولا يقيد المال.
- لا تَعرض واجهة الوكيل نجاحًا نهائيًا قبل تأكيد أميال باي ذي المعرّف غير المتكرر.

## المسار

1. عيّن العملية: إيداع نقدي، صرف نقدي، تحويل، شحن، عمولة، تسوية، عجز/زيادة، أو إدارة وردية.
2. عيّن الحيازة قبل وبعدها: العميل، الوكيل، خزينة أميال، أو حساب تسوية.
3. عيّن من يطلب ومن يعتمد ومن ينفذ ومن يراجع؛ لا يجتمع الطلب والاعتماد في حساب واحد لعملية تصحيح أو تسوية حساسة.
4. حدّد حد العملية وحد اليوم والسيولة المتاحة وحالة الوكيل والوردية قبل الإرسال.
5. أرسل طلبًا واحدًا إلى أميال باي مع `Idempotency-Key` ومعرّف الوكيل والوردية؛ لا يستقبل التطبيق مبلغًا محسوبًا كحقيقة نهائية.
6. سجّل مرجع العملية، المستخدم، الفرع/الجهاز، الوقت، الحيازة، والنتيجة في سجل تدقيق قابل للبحث.
7. صمّم حالات الواجهة: تحميل، نجاح نهائي، رفض بسبب حد/سيولة/KYC، انتظار، تكرار آمن، فشل اتصال، وتعافٍ بالبحث عن المرجع.
8. اختبر التوازي، إعادة إرسال الطلب، تغير حالة الوكيل، ونفاد السيولة قبل اعتماد الاكتمال.

## تسوية الوكيل

التسوية تقارن، ولا تخترع رصيدًا. يجب أن تعرض: النقد المتوقع، النقد المعدود، السيولة الإلكترونية، العمولة المستحقة، الفروقات، مراجع الحركات، والموافقات. الفارق يفتح حالة تحقيق؛ لا يعدّل قيودًا تاريخية مباشرة.

## قواعد صارمة

- لا `balance` قابل للكتابة في تطبيق أو خدمة الوكيل.
- لا نجاح محلي عند انقطاع الشبكة لعملية نقدية أو مالية.
- لا حذف أو تعديل لسجل وردية أو تسوية؛ التصحيح حدث أو قيد عكسي مسبب.
- لا تجاوز يدوي لحدود الوكيل إلا بموافقة مسجلة ومحددة الصلاحية.

## دليل الاكتمال

لا تعد العملية مكتملة حتى توجد: خريطة حيازة، عقد API، تفويض خادم، حماية التكرار، سجل تدقيق، اختبار فشل/إعادة إرسال، وتقرير تسوية قابل للتتبع.
